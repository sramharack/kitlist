# 0002: Python is the reference; Excel formulas do the work at runtime

- **Status:** accepted
- **Date:** 2026-11-07

## Context
Office users only ever open the workbook. When they change a load, the selected
size must update in Excel immediately, with no Python and no macros. But Excel
formulas are hard to test and review, while engineering rules need to be checked
carefully.

## Options considered
1. **Rules only as Excel formulas.** What users run, but untested and hard to review.
2. **Rules only in Python, values pasted into Excel.** Easy to test, but the
   workbook goes stale the moment someone changes an input.
3. **Both: each rule written once in Python (the reference implementation) and
   once as an Excel formula generated by the builder; tests check they agree.**

## Decision
Option 3. For example, `next_standard_size` in Python corresponds to this
Excel-2007-safe formula (sizes sorted ascending):

    =IFERROR(INDEX(Sizes, COUNTIF(Sizes, "<" & Target*(1-1E-9)) + 1), "EXCEEDS MAX")

From milestone M4, a test builds the workbook, recalculates it in LibreOffice,
and compares every Excel result with the Python result for the same inputs.

## Consequences
- Each rule exists twice, so the agreement test is mandatory, not optional.
- Python tests are fast and readable; they are where rules get designed and reviewed.
- Excel formulas stay limited to Excel-2007-era functions (no XLOOKUP, FILTER, LET)
  so the workbook works everywhere, including LibreOffice.
